# Verlet Physics

Салхинд хийсэх туг, савлах олс, шатнаас өнхрөх ragdoll, хэлбэлзэх желе — бүгд нэг л жор: **цэгүүд** ба тэдгээрийг холбосон **stick**-ууд. Цэг бүр зөвхөн хоёр зүйл санана: одоо хаана байгаа, өмнөх алхамд хаана байсан. 2001 онд Hitman тоглоомын хөгжүүлэгч Thomas Jakobsen энэ аргыг "Advanced Character Physics" илтгэлдээ тайлбарласнаас хойш тоглоомын физикийн сонгодог арга болсон.

## Энгийнээр хэлбэл

Нэг алхам (1/60 секунд) гурван хэсэгтэй:

| Алхам | Юу хийх вэ | Жишээ |
| --- | --- | --- |
| 1️⃣ **Хөдөлгөх** | Цэгийг өмнөх алхамд явсан шигээ дахин урагшлуулж, таталцал нэмнэ | Шидсэн бөмбөг цааш нисэнэ |
| 2️⃣ **Засах** | Stick бүрийг анхны уртад нь буцаана | Олс суналгүй, тасралтгүй байна |
| 3️⃣ **Давтах** | 2-р алхмыг хэд хэдэн удаа давтана | Олон удаа засах тусам илүү хатуу |

Хурд, хүч, эргэлт, тэгшитгэлийн систем — аль нь ч хэрэггүй. Үүнийг заримдаа **position-based** физик гэдэг: бид хурдыг биш, **байрлалыг** шууд засдаг.

## 1-р алхам: Verlet integration — хурдгүй хөдөлгөөн

Энгийн (Euler) арга хурдыг тусад нь хадгална:

$$
v \leftarrow v + a\,\Delta t, \qquad x \leftarrow x + v\,\Delta t
$$

Verlet харин хурдыг огт хадгалахгүй. Хурд бол **одоогийн ба өмнөх байрлалын зөрүү**:

$$
x_{\text{шинэ}} = x + \underbrace{(x - x_{\text{өмнөх}})}_{\text{хурд}} + a\,\Delta t^2
$$

**Жишээ:** цэг одоо $x = 10$-д, өмнөх алхамд $x_{\text{өмнөх}} = 8$-д байсан (алхам бүрт 2-оор урагшилж байна). Таталцлын нэмэгдэл $a\,\Delta t^2 = 1$.

- Хурд: $10 - 8 = 2$
- Шинэ байрлал: $10 + 2 + 1 =$ **13**
- Дараагийн алхамд $x_{\text{өмнөх}} = 10$, тиймээс хурд $13 - 10 = 3$ — таталцал хурдыг 1-ээр нэмсэн.

Яагаад энэ томьёо зөв бэ? Байрлалыг Taylor цуваагаар урагш, хойш нь задлаад нэмбэл:

$$
x(t+\Delta t) + x(t-\Delta t) = 2x(t) + a\,\Delta t^2 + O(\Delta t^4)
$$

Хурдны гишүүнүүд $\pm v\Delta t$ хоорондоо хасагдаж, $\Delta t^3$-ийн гишүүн ч мөн хасагдана. Үлдсэнийг шилжүүлбэл яг дээрх томьёо. Энэ **урагш, хойш тэгш хэм** нь Verlet-ийг тогтвортой болгодог: алдаа нь нэг зүг рүү хуримтлагдахгүй, хэлбэлзэнэ.

Хамгийн чухал давуу тал: **байрлалыг гараар зөөвөл хурд автоматаар өөрчлөгдөнө.** Stick цэгийг 1 пиксел татвал дараагийн алхамд тэр 1 пиксел хурд болж хувирна. Тиймээс бид хүч тооцоолохын оронд цэгүүдийг зөв газар нь л тавина.

## 2-р алхам: Stick — уртыг нь буцаах

Хоёр цэгийн хоорондох зай $d$, хүссэн урт $L$ бол хоёуланг нь stick-ийн дагуу **хагас хагасаар** нь зөөнө:

$$
\text{засвар} = \frac{d - L}{d} \cdot \frac{1}{2} \cdot (B - A)
$$

$A$ үүнийг нэмж $B$ рүү, $B$ хасаж $A$ руу ойртоно (эсвэл $d < L$ бол холдоно).

**Жишээ:** $A = (0, 0)$, $B = (5, 0)$, $L = 4$.

- $d = 5$, $\frac{d-L}{d} = \frac{1}{5} = 0.2$
- Засвар: $0.2 \cdot \frac12 \cdot (5, 0) = (0.5,\ 0)$
- $A = (0.5, 0)$, $B = (4.5, 0)$ → зай **4** ✓

**Масс.** Хүнд цэг бага хөдөлнө. Тиймээс засварыг $w = 1/m$ (урвуу масс) -аар хуваарилна. **Хадсан** цэг $w = 0$ — огт хөдлөхгүй. Дээрх жишээнд $A$-г хадвал $B$ бүх засварыг ганцаараа хийж, $(4, 0)$ болно. Demo-ийн төмөр бөмбөг $w = 0.05$, өөрөөр хэлбэл олсны цэгээс 20 дахин хүнд.

## 3-р алхам: Давтах

Олсны нэг stick-ийг засахад хөрш stick нь эвдэрнэ. Тэрийг засахад дараагийнх нь... Гэхдээ бүгдийг **хэд хэдэн удаа** тойруулж засвал бүх stick аажмаар зөв урттай болно. Үүнийг **relaxation** гэдэг.

Доорх C++ код 20 цэгтэй олсыг 2 секунд унжуулаад, нийт хэдэн хувь сунасныг хэмжсэн:

| Iterations | Олсны сунал |
| --- | --- |
| 1 | 39.09% |
| 2 | 11.58% |
| 5 | 5.47% |
| 10 | 2.35% |
| 20 | 1.16% |
| 50 | 0.42% |

Iteration цөөн → резин шиг сунамтгай. Олон → хатуу, гэхдээ удаан. Тоглоомууд ихэвчлэн 4–20 iteration-ийг сонгодог.

## Мөргөлдөөн — "гадна нь гаргачих"

Мөргөлдөөн бол бас нэг constraint: цэг шалан доор, бөмбөгөн дотор орсон бол **хамгийн ойрын гадаргуу дээр нь тавина**. Хурдыг ойлгох, тусгах хэрэггүй — Verlet байрлалын зөрүүнээс хурдыг өөрөө олно. Demo-д эдгээрийг stick-үүдийн хамт давталт бүрт шалгадаг; хоёр өөр биеийн цэгүүд мөн бие биеэ түлхдэг.

## Тасрах, хайчлах, ragdoll

- **Тасрах:** stick анхны уртаасаа 2.6 дахин сунавал устгана. Ердөө л жагсаалтаас хасна.
- **Хайчлах:** хулганы зурсан шугамтай огтлолцсон stick-үүдийг устгана.
- **Ragdoll:** яс бол stick. Өвдөг, хүзүү хэт нугалахаас сэргийлэхийн тулд **"min" stick** нэмнэ — тэр зөвхөн хоёр цэг хэт ойртох үед түлхэнэ, холдоход юу ч хийхгүй. Жишээ нь хонго ба хөлийн ул хоорондын зай хэзээ ч анхныхаасаа 55%-иас бага болохгүй.
- **Зөөлөн бие:** цагираг цэгүүд + төв рүү чиглэсэн spoke. Spoke-ийн хатуулаг $k = 1$ бол дугуй, $k \approx 0.03$ бол желе.

## Сул тал

- **Хатуулаг iteration-ээс хамаарна.** Ижил stick 5 ба 40 iteration-д өөр мэдрэмжтэй. 2016 оны **XPBD** (Macklin, Müller, Chentanez) үүнийг засаж, хатуулгийг физикийн нэгжээр өгдөг болгосон.
- **Энерги аажмаар алдагдана.** Засвар бүр бага зэрэг "үрэлт" нэмдэг. Тоглоомд энэ нь давуу тал — систем дэлбэрэхгүй, тогтворжино.
- **Нарийвчлал биш, итгэл үнэмшил.** Инженерийн тооцоонд илүү нарийн арга хэрэгтэй. Харин нүдэнд бодит харагдах, хурдан ажиллахад Verlet хамгийн энгийн сонголт.

## Demo дээр туршаад үз

- **Даавуу 🧣**-г **Чирэх ✋**-ээр хүчтэй тат — хэт сунасан stick тасарна. **Хайчлах ✂️**-аар зүсээд үз.
- **Iterations**-ийг 1 болго, дараа нь 40 — даавуу резин мэт сунаж, дахин хатуурна. **Суналтыг өнгөөр** асаавал хаана хамгийн их сунаж буйг улаанаар харуулна.
- **Хадах 📌**-аар дээд мөрийн хадаасыг авбал даавуу унана. Доод булангуудыг хадвал хөшиг болно.
- **Олс 🪢**: хүнд бөмбөг хөнгөн олсыг сунгаж байгааг хар. Гүүрний олсыг хайчил.
- **Ragdoll 🤸** ба **Зөөлөн бие 🟢**: **＋ Нэмэх**-ээр шинээр унага. **Бүтэц**-ийг асаавал далд stick-ууд (желений spoke, хайрцгийн diagonal, ragdoll-ийн улаан тасархай хязгаар) харагдана.
- **Хурд = x − x_prev** асаа — шар зураас бол хурд, гэхдээ тусдаа хадгалагдаагүй: зөвхөн хоёр байрлалын зөрүү.
- Зогсоогоод **⏭ Алхам**-аар нэг нэг алхамаар үз.

## Нэг санаа авч үлдэх

> **Хүчийг биш, байрлалыг зас — хурд өөрөө зөв гарч ирнэ.** Ragdoll, нөмрөг, олс, гүүр, машины хонхойлт — бүгд "цэгийг хөдөлгө, stick-ийг зас, давт" гэсэн гурван мөр.

## Код (C++)

Дээрх хүснэгтийг гаргасан бүтэн программ:

```cpp
#include <cmath>
#include <cstdio>
#include <vector>
using namespace std;

struct Point { double x, y, px, py; bool pinned; };
struct Stick { int a, b; double len; };

// Олсыг iterations давталттайгаар 2 секунд симуляц хийгээд, хэдэн хувь сунасныг буцаана.
double simulate(int iterations) {
    const int N = 20;                 // 20 цэг, 19 stick
    const double dt = 1.0 / 60, g = 9.8, seg = 0.1;
    vector<Point> p;
    vector<Stick> s;
    for (int i = 0; i < N; i++) p.push_back({0, i * seg, 0, i * seg, i == 0}); // доош унжсан, оройг хадсан
    for (int i = 0; i + 1 < N; i++) s.push_back({i, i + 1, seg});

    for (int step = 0; step < 120; step++) {
        // 1) Verlet: x_шинэ = x + (x - x_өмнөх) + g·dt²
        for (Point& q : p) {
            if (q.pinned) continue;
            double vx = q.x - q.px, vy = q.y - q.py;
            q.px = q.x; q.py = q.y;
            q.x += vx;
            q.y += vy + g * dt * dt;
        }
        // 2) Stick бүрийг уртад нь буцаах — iterations удаа
        for (int it = 0; it < iterations; it++)
            for (const Stick& k : s) {
                Point &a = p[k.a], &b = p[k.b];
                double dx = b.x - a.x, dy = b.y - a.y, d = sqrt(dx * dx + dy * dy);
                double wa = a.pinned ? 0 : 1, wb = b.pinned ? 0 : 1;
                double c = (d - k.len) / (d * (wa + wb));
                a.x += dx * c * wa; a.y += dy * c * wa;
                b.x -= dx * c * wb; b.y -= dy * c * wb;
            }
    }
    double total = 0;
    for (const Stick& k : s) total += hypot(p[k.b].x - p[k.a].x, p[k.b].y - p[k.a].y);
    return (total / (seg * (N - 1)) - 1) * 100;
}

int main() {
    for (int it : {1, 2, 5, 10, 20, 50})
        printf("iterations = %2d  ->  олс %.2f%% сунасан\n", it, simulate(it));
}
```

```

iterations =  2  ->  олс 11.58% сунасан
iterations =  5  ->  олс 5.47% сунасан
iterations = 10  ->  олс 2.35% сунасан
iterations = 20  ->  олс 1.16% сунасан
iterations = 50  ->  олс 0.42% сунасан
```
